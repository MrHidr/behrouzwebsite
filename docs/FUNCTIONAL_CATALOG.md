# فهرست امکانات و صفحات

## مسیرهای عمومی

| مسیر | کارکرد | محتوای اصلی قابل مدیریت |
|---|---|---|
| `/` | صفحهٔ اصلی | hero، مسیرهای محصول، معرفی، زنجیره ارزش، footer |
| `/about` | دربارهٔ بهروز | تاریخچه، مقیاس، ارزش‌ها، افتخارات، مسیر بین صفحات، CTA |
| `/innovation` | نوآوری | داستان R&D، چرخه/سبد، آزمایشگاه، کشاورزی، کیفیت، CTA |
| `/production` | تولید | سفر محصول، کارخانه، تحویل، مسیر بین صفحات، CTA |
| `/distribution` | توزیع | وعده، شبکه، مسیر، فروش، توانمندی، رهبری، همکاری |
| `/production-distribution` | سازگاری لینک قدیمی | redirect به `/distribution` |
| `/contact` | تماس با ما | موقعیت‌ها، نقشه/جست‌وجو، کانال‌ها، واحدها، صدای مشتری |
| `/careers` | همکاری با ما | hero، معرفی کوتاه فرهنگ و زمینه‌های کاری، فرم درخواست همکاری |
| `/products` | ورودی محصولات | redirect به دسته‌ها در صفحهٔ اصلی |
| `/products/[slug]` | صفحهٔ یک دسته محصول | دسته، زیردسته، محصول، تصویر/ویدئو، ترتیب و مشخصات |
| مسیر ناشناخته | صفحهٔ 404 | پیام و مسیر بازگشت |

slugهای فعلی دسته‌های محصول: sauces، canned، jam، pickles، gherkin و lime-juice.

## مدل صفحات در CMS

هر صفحه رکورد ثابت خود را دارد. hero اصلی حذف یا hide نمی‌شود. سکشن‌های دیگر، هرجا طراحی اجازه دهد، گزینهٔ «نمایش این سکشن» دارند. فهرست‌های طبیعی مثل موقعیت‌ها، کانال‌ها، واحدها، لینک‌ها یا واریانت‌ها قابل افزودن، حذف و مرتب‌سازی هستند؛ فیلدهای سازه‌ای برای جلوگیری از خرابی UI حذف‌پذیر نیستند.

| صفحه | سکشن‌های تعریف‌شده |
|---|---|
| خانه | hero ثابت، مسیرها |
| درباره | hero ثابت، داستان، مقیاس، ارزش‌ها، افتخارات، cross journey، قدم بعد |
| نوآوری | hero ثابت، داستان، portfolio، آزمایشگاه، کشاورزی، کیفیت، cross journey، قدم بعد |
| تولید | hero ثابت، داستان، کارخانه، handoff، cross journey، قدم بعد |
| توزیع | hero ثابت، وعده، شبکه، مسیر، فروش، توانمندی، رهبری، همکاری |
| تماس | hero ثابت، فهرست موقعیت‌ها، فهرست کانال‌ها و واحدها، feedback |
| همکاری با ما | hero ثابت، فرهنگ سازمانی، زمینه‌های کاری و فرم درخواست |

## مجموعه‌ها و تنظیمات CMS

| بخش | ایجاد رکورد | حذف رکورد | توضیح |
|---|---:|---:|---|
| کاربران پنل | بله | بله، به‌جز خود کاربر جاری | حساب بازدیدکننده یا مشتری نیست |
| دستهٔ محصول | بله | با دسترسی مناسب | عنوان، slug، صحنه و ترتیب |
| زیردستهٔ محصول | بله | با دسترسی مناسب | محدودیت یکتایی و ارتباط معتبر با دسته |
| محصول | بله | فقط با مدیریت محصول + انتشار | جزئیات، ترتیب، اندازهٔ visual، رسانه و وضعیت انتشار |
| صفحات | خیر | خیر | ۷ رکورد ثابت، سکشن‌بندی کنترل‌شده |
| رسانه | بله | بله | jpeg/png/webp/avif/mp4/pdf تا ۲۵MB؛ SVG و URL paste ممنوع |
| درخواست‌های همکاری | فقط فرم عمومی | مدیر مجاز | نام، تلفن، رزومه‌ها، وضعیت بررسی و یادداشت داخلی |
| فایل‌های رزومه | فقط فرم عمومی | همراه درخواست | خصوصی؛ PDF/DOC/DOCX با نام ذخیره‌سازی تصادفی |

نسخه‌های draft و published از هم جدا هستند و حداکثر ۳۰ نسخهٔ قبلی نگهداری می‌شود.

## دسترسی کاربران پنل

اولین کاربر به‌صورت خودکار مدیر اصلی می‌شود و تمام دسترسی‌ها را دارد. مدیر اصلی برای هر کاربر چک‌باکس‌های مستقل زیر را تنظیم می‌کند:

- مدیریت کاربران و دسترسی‌ها
- افزودن و تغییر محصولات، دسته‌ها و زیردسته‌ها
- تغییر متن و تصاویر صفحات
- تغییر تنظیمات عمومی، منو، فوتر و SEO
- بارگذاری، تغییر و حذف رسانه‌ها
- انتشار یا لغو انتشار محتوا
- مشاهدهٔ گزارش فعالیت‌ها
- مشاهده و مدیریت درخواست‌های همکاری

کاربر بدون «انتشار» می‌تواند در حوزهٔ مجاز خود پیش‌نویس بسازد، اما محتوای عمومی فقط وضعیت published را می‌بیند. نقش‌های داخلی قدیمی صرفاً برای سازگاری migration باقی مانده‌اند؛ رابط کسب‌وکار بر چک‌لیست فوق تکیه دارد.

## رفتار رسانه

- تصویر فعلی کنار فیلد جایگزین قابل مشاهده است و آپلود جدید از کتابخانهٔ رسانه انتخاب می‌شود.
- رسانهٔ قدیمی همراه source است؛ به همین دلیل نصب تازه ممکن است کتابخانهٔ CMS خالی داشته باشد.
- رسانهٔ جدید روی Linux در volume یا S3 و روی Cloudflare در R2 قرار می‌گیرد.
- مقدار اندازهٔ محصول `small`، `normal` یا `large` است و به‌ترتیب ارتفاع نمایشی ۹۵٪، ۱۰۰٪ یا ۱۰۵٪ می‌دهد.
- alt فارسی/انگلیسی برای تصاویر الزامی است.

## فرم همکاری با ما

- تعداد فایل، سقف هر فایل، سقف مجموع، نوع‌های مجاز و مدت نگهداری از «تنظیمات سایت ← همکاری با ما» قابل تنظیم‌اند.
- سقف امنیتی برنامه مستقل از پنل است: حداکثر ۵ فایل، ۱۰MB برای هر فایل و ۲۰MB در مجموع؛ مدیر نمی‌تواند سهواً از این مرزها عبور کند.
- فرمت‌های قابل انتخاب PDF، DOC و DOCX هستند. فقط پسوند بررسی نمی‌شود و امضای داخلی فایل نیز کنترل می‌شود.
- فایل رزومه وارد کتابخانهٔ عمومی رسانه نمی‌شود و collection/storage خصوصی جداگانه دارد.
- مدیر مجاز می‌تواند وضعیت درخواست را تغییر دهد و یادداشت داخلی بگذارد. اطلاعات متقاضی در log به‌صورت مقدار خام ثبت نمی‌شود.
- پاک‌سازی درخواست‌های قدیمی و فایل‌های وابسته با job دوره‌ای انجام می‌شود.
- روی Linux هر فرم token امضاشدهٔ یک‌بارمصرف دارد؛ rate limit داخلی Redis به‌صورت پیش‌فرض ۵ درخواست در ۱۵ دقیقه برای هر IP و ۱۰۰ درخواست در ساعت برای کل فرم است.
- IP خام در Redis یا log ذخیره نمی‌شود و کلید محدودسازی با HMAC ناشناس می‌شود. یک شماره نیز حداکثر دو ارسال در بازهٔ پیش‌فرض ۲۴ ساعت دارد.

## افزودن صفحه در آینده

افزودن صفحهٔ جدید یک تغییر نرم‌افزاری است، نه صرفاً عملیات پنل. توسعه‌دهنده باید route و component، تعریف سکشن، گزینهٔ page key، seed، migration هر دو دیتابیس، typeهای Payload، navigation/SEO و تست responsive را اضافه کند. پس از آن همان صفحه در پنل برای تیم محتوا قابل مدیریت خواهد بود.
