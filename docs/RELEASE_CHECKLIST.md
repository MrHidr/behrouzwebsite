# چک‌لیست انتشار و تحویل

## مالکیت و ورودی‌ها

- [ ] repository سازمانی، owner و maintainerها مشخص‌اند.
- [ ] مسیر Linux یا Cloudflare و محیط‌های staging/production تصویب شده‌اند.
- [ ] دامنه، DNS، TLS و پنجرهٔ انتشار مشخص‌اند.
- [ ] RPO، RTO، retention و مسئول incident تصویب شده‌اند.
- [ ] مقصد ایمیل و media storage مشخص‌اند.
- [ ] مالک داده‌های متقاضی، مدت نگهداری رزومه و مقصد storage خصوصی تصویب شده‌اند.

## کد و داده

- [ ] CI روی commit/tag تحویلی سبز است.
- [ ] `package-lock.json` با `npm ci` سازگار است.
- [ ] typeهای Payload و Cloudflare به‌روزند.
- [ ] هر تغییر schema دارای migration PostgreSQL و D1 است.
- [ ] seed روی دادهٔ production دوباره و بدون دلیل اجرا نمی‌شود.
- [ ] هیچ secret، `.env`، dump یا asset خام در Git/image وجود ندارد.
- [ ] فهرست صفحات و تعداد محصولات با محتوای مورد تأیید کسب‌وکار تطبیق دارد.

## امنیت

- [ ] مقدارهای نمونه و placeholder از config مقصد حذف شده‌اند.
- [ ] secretها در secret manager و با حداقل دسترسی ثبت شده‌اند.
- [ ] HTTPS اجباری است و DB مستقیماً به اینترنت باز نیست.
- [ ] `/admin` و endpointهای حساس پشت کنترل دسترسی و rate limit هستند.
- [ ] `/api/careers/apply` پشت Nginx rate limit، Redis داخلی و token یک‌بارمصرف است؛ در صورت الزام، CAPTCHA/WAF تکمیلی نیز تست شده است.
- [ ] حساب‌ها شخصی‌اند و چک‌لیست مجوز هر کاربر بازبینی شده است.
- [ ] dependency و container scan نتیجهٔ قابل قبول دارند.
- [ ] فرایند لغو دسترسی و rotation secret مستند شده است.

## backup و بازگشت

- [ ] پیش از release از دیتابیس و رسانه snapshot سازگار گرفته شده است.
- [ ] restore در staging واقعاً اجرا و نتیجه ثبت شده است.
- [ ] tag/image قبلی برای rollback در دسترس است.
- [ ] اثر migration بر rollback بررسی شده است.

## آزمون پذیرش staging

- [ ] `/healthz` پاسخ موفق می‌دهد.
- [ ] صفحهٔ خانه، شش صفحهٔ سازمانی و شش دستهٔ محصول باز می‌شوند.
- [ ] فارسی/انگلیسی و جهت RTL/LTR درست است.
- [ ] login، logout، lockout و بازیابی رمزِ فعال‌شده تست شده‌اند.
- [ ] مدیر اصلی می‌تواند کاربر و چک‌باکس‌های مجوز را مدیریت کند.
- [ ] کاربر محدود نمی‌تواند خارج از مجوز خود تغییر ایجاد کند.
- [ ] draft در سایت عمومی دیده نمی‌شود و publish دیده می‌شود.
- [ ] upload تصویر و ویدئوی مجاز، نمایش preview و حذف کنترل‌شده تست شده‌اند.
- [ ] فایل نامجاز و فایل بزرگ‌تر از ۲۵MB رد می‌شود.
- [ ] فرم همکاری با فایل معتبر ثبت می‌شود و فایل جعلی، تعداد/حجم بیش از تنظیم و Origin نامعتبر رد می‌شود.
- [ ] token تکراری رد می‌شود، سقف IP/global پاسخ ۴۲۹ می‌دهد و خرابی Redis در production فرم را fail-closed می‌کند.
- [ ] رزومه بدون ورود/مجوز مستقیم قابل دریافت نیست و فقط مدیر دارای دسترسی درخواست‌ها را می‌بیند.
- [ ] job حذف درخواست‌های منقضی اجرا و حذف فایل وابسته در staging تأیید شده است.
- [ ] activity log برای create/update/delete ساخته می‌شود.
- [ ] ایمیل/شمارهٔ سازمانی در UI درست و بدون لینک متنی مستقیم نمایش داده می‌شود.
- [ ] mobile، tablet و desktop روی مرورگرهای مورد تأیید بررسی شده‌اند.

## انتشار production

- [ ] maintenance/change record آغاز شده است.
- [ ] migration بدون خطا تمام شده است.
- [ ] app/Worker نسخهٔ موردنظر اجرا شده است.
- [ ] health داخلی و خارجی موفق است.
- [ ] smoke test سایت، پنل، رسانه و انتشار موفق است.
- [ ] مانیتورینگ و alert در حال دریافت داده‌اند.
- [ ] backup پس از انتشار ثبت شده است.
- [ ] کسب‌وکار محتوای production را تأیید کرده است.
